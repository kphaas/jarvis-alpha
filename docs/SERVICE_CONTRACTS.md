## 1. Approval Gateway

### Lifecycle

```
Client Request
    ↓
Middleware classifies route → risk tier
    ↓
T1: pass through (no audit)
T2: pass through + fire-and-forget audit INSERT
T3: pass through + audit INSERT + notification marker
T4/T5: block → queue INSERT → 403 response → notification
    ↓
User opens Approvals UI → enters PIN → 5-min approval token
    ↓
Approve/Deny via /v1/approvals/{id}/decide
    ↓
If approved: client retries original request within 10 min
    ↓
Middleware sees approved row → passes request through → marks 'executed'
```

### 403 Response (T4/T5 blocked)

```json
{
  "detail": "approval_required",
  "queue_id": "uuid-string",
  "tier": "T5",
  "action_class": "destructive"
}
```

### POST /v1/approvals/unlock

Request:
```json
{ "pin": "1234" }
```

Response:
```json
{
  "approval_token": "eyJ...",
  "expires_in": 300
}
```

Token has `"purpose": "approval"` claim. 5-minute TTL.

### GET /v1/approvals/pending

Response:
```json
{
  "pending": [
    {
      "id": "uuid",
      "action_class": ["destructive"],
      "risk_tier": "T5",
      "actor_sub": "ken",
      "actor_type": "user",
      "description": "DELETE /v1/memory/test123",
      "status": "pending",
      "requested_at": "ISO8601",
      "expires_at": "ISO8601",
      "overnight": false
    }
  ],
  "count": 1
}
```

### POST /v1/approvals/{id}/decide

Headers required:
- `Authorization: Bearer <user_jwt>`
- `X-Approval-Token: <approval_token>`

Request:
```json
{ "decision": "approved" }
```
or
```json
{ "decision": "denied" }
```

Response:
```json
{
  "queue_id": "uuid",
  "decision": "approved",
  "description": "DELETE /v1/memory/test123",
  "expires_at": "ISO8601"
}
```

On approve: queue row status → 'approved', new 10-min expires_at.
On deny: queue row status → 'denied', no expires_at.

## 2. Buddy Events

### Purpose
Central notification feed. UI polls `/v1/buddy/events`. Services write events for visibility.

### Writing a Buddy Event

```python
import json
from brain.db.pool import get_pool

pool = get_pool()
async with pool.acquire() as conn:
    await conn.execute(
        """INSERT INTO alpha_buddy_events
           (event_type, title, body, priority, source, payload)
           VALUES ($1, $2, $3, $4, $5, $6)""",
        "alert",                          # event_type: alert|reminder|suggestion|system
        "Title here",                     # title
        "Detailed body text",             # body (nullable)
        2,                                # priority: 1=normal, 2=high
        "my_service",                     # source identifier
        json.dumps({"key": "value"}),     # payload — MUST be json.dumps()
    )
```

### Current Sources

| Source | Writes | Event Types |
|---|---|---|
| approval_gateway | T4/T5 queue notifications | alert |
| token_rotation | Rotation failures | alert |
| buddy_agent | Memory promotions, stuck tasks | suggestion, system |

### Reading Events (UI)

```
GET /v1/buddy/events
```

Polling interval: 10 seconds. WebSocket upgrade planned Alpha-3.

## 3. Approval Notifications

### Notification Payload Shape

Generated by `brain/services/approval_notifier.py`:

```python
{
    "title": "JARVIS Approval Required — T5",
    "body": "T5 · destructive\nDELETE /v1/memory/test123\n\nRequested by: ken (user)\n...",
    "priority": 2,       # 2 for T5, 1 for T4
    "payload": {
        "queue_id": "uuid",
        "tier": "T5",
        "action_classes": ["destructive"],
        "method": "DELETE",
        "path": "/v1/memory/test123",
        "actor_sub": "ken",
        "actor_type": "user",
        "overnight": false
    }
}
```

### Delivery Chain (current)

```
T4/T5 queued → approval_notifier.send_approval_notification()
    → log + INSERT alpha_buddy_events (source='approval_gateway')
    → record_agent_event(agent_id='approval_triage', severity='needs_input')
    → SkillPolicyGate permits notify.send for approval_triage
    → SkillRunner notify.send
        → POST to Gateway /v1/notify/mattermost
        → Gateway posts to Mattermost incoming webhook
        → Pushover fallback only if Mattermost is unavailable
    → mark_agent_event_notification(sent | fallback_sent | denied | failed)
```

## 4. PIN Authentication

### POST /v1/auth/pin

Request:
```json
{ "pin": "1234", "profile_id": "ken" }
```

Response:
```json
{
  "token": "eyJ...",
  "expires_at": "2026-05-06T..."
}
```

JWT claims:
```json
{
  "sub": "ken",
  "iss": "user",
  "role": "admin",
  "actor_type": "user",
  "max_rating": "adult",
  "scopes": ["*"],
  "exp": 1778058602
}
```

Token lifetime: 30 days. Stored in `localStorage` as `alpha_token`.
Child profiles get restricted scopes: `["ask", "chat.read", "health.read"]`.

## 5. Service Token Authentication

### Token Shape (service-to-service)

```json
{
  "sub": "buddy_agent",
  "iss": "brain",
  "actor_type": "service",
  "scopes": ["memory.read", "memory.write", "tasks.read", "tasks.write", "buddy.write"],
  "exp": 1778058602
}
```

### Rotation

- Script: `scripts/rotate_service_token.py --node {brain,gateway,sandbox}`
- LaunchAgent: fires every 5 days (432000s)
- Atomic update: temp file → os.rename → chmod preserved
- Constants: `scripts/service_identity.py` (VALID_ISS_ACTOR_PAIRS, DEFAULT_SCOPES)

### Rotation Failure Alert

On failure, rotation script INSERTs a buddy event:
```python
event_type = "alert"
source = "token_rotation"
payload = json.dumps({"node": "gateway", "error": "..."})
```

## 6. Route Classification

### Classification Registry

File: `brain/middleware/approval_classes.py`

```python
ROUTE_CLASSIFICATION = {
    "GET /v1/my/route": ["read"],           # → T1
    "POST /v1/my/route": ["write"],          # → T2
    "DELETE /v1/my/thing/{id}": ["destructive"], # → T5
}
```

### Tier Rules (first match wins)

| Action Class(es) | Tier | Behavior |
|---|---|---|
| approval_decide | T2 | Prevents deadlock |
| approval_unlock | T2 | Prevents deadlock |
| deploy + child_facing | T5 | Highest risk compound |
| unclassified | T5 | Deny by default |
| destructive | T5 | Block + queue |
| admin | T5 | Block + queue |
| deploy | T4 | Block + queue |
| child_facing | T4 | Block + queue |
| cost_incurring | T3 | Pass + audit + notify |
| external_call | T2 | Pass + audit |
| write | T2 | Pass + audit |
| security_read | T2 | Pass + audit |
| read | T1 | Pass through |

### Startup Audit

On Brain boot, `brain/middleware/approval_audit.py` scans all routes:
- Missing routes → WARNING with list
- All classified → INFO confirmation
- Grep: `grep "ROUTE_AUDIT" ~/jarvis-alpha/logs/alpha_brain.log`

## 7. Memory System

### 3-Tier Architecture

| Tier | Lifetime | Managed By |
|---|---|---|
| Working | 24 hours | Buddy evicts expired |
| Episodic | 30 days | Buddy scores + promotes |
| Semantic | Permanent | Promoted from episodic |

### Retrieval (RAG)

Two-phase: HNSW ANN first (fast recall) → cosine rerank (precision).
Embeddings: 768-dimensional vectors.

### Memory Sources

| Source Tag | Meaning |
|---|---|
| live | Created during active conversation |
| thread_extract | Extracted before thread deletion |
| overnight | Created by Dream Mode |
| ingest | Bulk ingested from documents |

## 10. UI → Brain

### apiFetch Pattern

All API calls go through `ui/src/lib/apiFetch.ts`:
- Auto-injects `Authorization: Bearer <token>` from localStorage
- Base URL: Brain at `:8186` via nginx proxy on Endpoint `:4100`

### Approval-Specific Headers

The decide endpoint requires an additional header:
```typescript
headers: {
  'Content-Type': 'application/json',
  'X-Approval-Token': approvalToken,
}
```

This token is separate from the main JWT — it's a 5-minute purpose-scoped token from `/v1/approvals/unlock`.
