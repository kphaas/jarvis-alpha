## Architecture Decisions Locked

### Telemetry v2 (13 decisions)

1. Wide-event envelope schema with hot columns + JSONB tail (NOT generic blob)
2. Partition `alpha_telemetry_events` by `event_time` RANGE (daily)
3. DROP PARTITION for retention, NOT DELETE (avoids vacuum debt)
4. Priority queue classes by `event_family` — billing/governance never drop
5. `dedupe_key` + idempotent retries for billing-class events
6. Daily reconciliation against provider billing APIs (Anthropic, Google, Perplexity)
7. Separate `event_time` (wall-clock) and `ingested_at` (DB write time) columns
8. Dapper-style span identity: `run_id`, `trace_id`, `span_id`, `parent_span_id`
9. Schema registry as `common/jarvis_common/telemetry/schemas/` directory with Pydantic models per `(event_name, schema_version)`
10. Exporter as ABC interface — `PostgresExporter` first, `OtelCollectorExporter` later (one-file swap)
11. `tenant_project_id` as primary RLS isolation column, NOT `profile_id`
12. Dedicated `jarvis_alpha_telemetry_writer` role with role-based RLS (NOT SECURITY DEFINER — telemetry exception)
13. Configurable flush via env vars: `TELEMETRY_FLUSH_SECONDS`, `TELEMETRY_FLUSH_BATCH`, `TELEMETRY_QUEUE_MAX`, `TELEMETRY_EXPORTER`, `TELEMETRY_DROP_DEBUG_OVER_PCT`

### Child RLS Hybrid C v2 (10 decisions)

1. Hybrid C — workspace ownership AND content tier, two independent checks
2. SMALLINT tiers with `alpha_content_tiers` lookup table (NOT TEXT + tier_rank function)
3. 5-tier hospital model: `public(0) | kids(1) | teen(2) | adult(3) | sensitive_adult(4)`
4. Partition `alpha_conversation_memory` by `content_tier` LIST — separate HNSW per partition (HNSW hard boundary, not just RLS-as-WHERE)
5. SECURITY DEFINER functions for ALL background writes — no `_none` sentinel role
6. `FORCE ROW LEVEL SECURITY` on every sensitive table
7. Fail-closed policies — NULL `jarvis.profile_id` or `jarvis.max_tier` denies all
8. Surface persisted in DB session context AND enforced in middleware (defense in depth at request level)
9. Python `contextvars`-based auth propagation across async boundaries (TaskGraph)
10. Default tier on INSERT = inserter's max_tier, with `WITH CHECK` forbidding writes above actor tier
11. No per-profile per-workspace tier overrides (avoid exception debt)
12. Denied-read audit lives in app layer (Postgres has no native pattern)
13. Children authenticate ONLY via Voice/Avatar surfaces — never the dashboard

### System-Wide Rule

**Background service write pattern depends on data class:**

| Data class | Pattern | Examples |
|---|---|---|
| Profile-bearing user data | SECURITY DEFINER functions | memory, chat, documents, Family Vault |
| Infrastructure observability | Dedicated writer role + role-based RLS | telemetry, watchdog, metrics |

This split came from the convergence test between the two Perplexity reviews — they disagreed on background writes, and the disagreement was meaningful (different data classes, different threat models).

## Perplexity Review Quality

Both reviews delivered substantive critique, not soft validation. Key learnings:

### Telemetry review highlights
- "Wide-event envelope, not generic blob" — pushed back on my naive JSONB-only approach
- "Drop oldest is wrong for billing-class events" — caught the priority queue gap
- "Stop using profile_id as the main isolation concept for telemetry" — correct security primitive distinction
- Recommended Stripe-style idempotency keys for billing events
- Recommended daily reconciliation against provider billing APIs

### Child RLS review highlights
- "Drop the `_none` background identity" — caught a bypass vector in current jarvis-core pattern
- "Use SMALLINT tiers, not TEXT + rank function" — performance + clarity win
- "HNSW + RLS-as-WHERE is not a security boundary" — the hidden landmine, planner runs ANN before RLS filter
- Recommended Epic MyChart proxy access model as precedent for parent-child access
- Recommended `FORCE ROW LEVEL SECURITY` everywhere (default RLS bypasses owner role)

### Convergence test result

Both reviews touched background-service writes. They disagreed:

| Review | Recommendation |
|---|---|
| Child RLS | SECURITY DEFINER functions, no broad system role |
| Telemetry | Trusted writer role with `WITH CHECK` |

The disagreement was meaningful — they're addressing different data classes. Resolution: both patterns coexist, system-wide rule documented above.

This is exactly the kind of nuance that emerges from running parallel reviews. Worth the extra time.
