### 3. Dream Mode Brain Routes
- File: brain/routes/dream.py (354 lines)
- 8 endpoints: create session, list, detail, start, kill, next-step, update step, complete
- State machine: VALID_STEP_TRANSITIONS enforced on every PATCH

- Failed parent → children auto-blocked
- Cost budget check before returning next step
- Scope enforcement: `check_scopes(request, "dream.execute")` on all write routes

### 4. Dream Mode Gateway Orchestrator
- File: gateway/dream/orchestrator.py (358 lines)
- Uses curl + asyncio.to_thread (httpx fails with Tailscale TLS)
- Circuit breaker: MAX_CALLS_PER_SESSION = 200
- Wall-clock watchdog: kills session at max_duration_s
- Retry with backoff: [5, 15, 45] seconds
- Post-action verification: _verify_output checks non-empty summary + verification
- Dispatchers: canary (health probe), llm (Ollama), cloud (Claude), tool (stub)
- Dry-run mode: simulates all steps without real LLM calls
- CLI: `python3 -m gateway.dream.orchestrator --session-file /path/to/session.json [--dry-run]`

### 5. Dream Mode Kill Switch CLI
- File: gateway/dream/kill_switch.py (112 lines)

- Private keys never leave the node they were generated on
- Endpoint skipped intentionally — pure presentation, no secrets

### 7. Service Token Generator
- File: scripts/gen_service_token.py (134 lines)
- VALID_ISS_ACTOR_PAIRS: gateway/service, sandbox/service, buddy/agent, endpoint/service (future-proofed)
- DEFAULT_SCOPES per issuer
- 7-day token lifetime
- `--json` flag shows full claims
- Requires PyJWT[crypto] on each node

### 8. Multi-Issuer JWT Auth Middleware
- File: brain/middleware/jwt_auth.py (113 lines)
- _KEY_REGISTRY: maps issuer name → public key path
- Auto-discovers ~/jarvis/pki/services/*_public.pem at startup
- Backward compat: user tokens (no iss or iss=user) → existing jwt_public.pem
- Unverified decode to read iss → lookup correct public key → verified decode
- Sets request.state.actor_type, .scopes, .iss after decode

### 9. Scope Enforcement
- File: brain/middleware/scopes.py (65 lines)
- `check_scopes(request, "scope1", "scope2")` — inline function, not decorator
- Admin users (role=admin) bypass all scope checks
- Wildcard scope ["*"] bypasses all checks
- Returns 403 with required_scopes + your_scopes in response
- Wired to dream routes (create, start, kill, next-step, update, complete)

### 10. Child Profile System
- Migration: brain/migrations/009_child_profiles.sql (121 lines)
- `alpha_profiles` table: id, display_name, role, child_age, max_rating, pin_hash, active
- 3 profiles seeded: ken (admin/adult), ryleigh (child/8/age_8_plus), sloane (child/5/all_ages)
- Content rating system: all_ages(1) → age_8_plus(2) → teen(3) → adult(4)
- `rating_level()` Postgres function for numeric comparison (not lexicographic)
- content_rating columns added to: chat_messages, chat_threads, alpha_conversation_memory
- owner_profile columns added to: chat_threads, alpha_task_graphs, alpha_dream_sessions

### 11. Child RLS Policies (8 policies)
- child_thread_isolation: children see only their own threads
- child_message_isolation: children see only messages in their threads
- child_content_rating: content_rating <= max_rating (via rating_level())
- child_memory_rating: same for conversation memory
- child_memory_write: only admin can write memory
- child_task_isolation: only admin can access task graphs
- child_dream_isolation: only admin can access dream sessions
- child_dream_step_isolation: only admin can access dream steps
- RLS enabled on: chat_threads, chat_messages, alpha_task_graphs, alpha_dream_sessions, alpha_dream_steps

### 12. jarvis_alpha_app Postgres Role
- NOLOGIN, NOSUPERUSER, NOBYPASSRLS
- GRANT SELECT/INSERT/UPDATE/DELETE on all tables
- GRANT USAGE/SELECT on all sequences
- Default privileges set for future tables
- jarvisbrain granted jarvis_alpha_app role

### 13. RLS Connection Helper
- File: brain/db/rls.py (45 lines)
- `rls_connection(request)` async context manager
- SET ROLE jarvis_alpha_app → set_config (profile_id, profile_role, max_rating, user_id) → yield → RESET ROLE

### 14. Profile-Based PIN Auth
- File: brain/routes/pin_auth.py (129 lines)
- PinRequest accepts optional profile_id (default "ken")
- Lookup profile in alpha_profiles
- PLACEHOLDER_MIGRATE_FROM_ALPHA_PIN → checks ALPHA_PIN secret (backward compat)
- Other PLACEHOLDER → rejects with "PIN not configured"
- Live pin_hash → bcrypt.checkpw
- JWT claims include: sub, iss, role, profile_id, display_name, actor_type, max_rating, scopes, child_age
- Child scopes: ["ask", "chat.read", "health.read"]
- Admin scopes: ["*"]

### 15. Child PIN Management

- Accepts profile_id + new_pin
- Stores bcrypt hash in alpha_profiles
- Ryleigh PIN set and tested
