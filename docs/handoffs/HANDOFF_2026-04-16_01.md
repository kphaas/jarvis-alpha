### What Was Done

1. **next-step POST→GET mismatch fixed** — `ROUTE_CLASSIFICATION` had `POST /v1/dream/sessions/{session_id}/next-step` but the actual route is GET. Most critical Dream Mode endpoint was missing its `cost_incurring` approval tier classification.

2. **11 phantom entries removed** (original estimate was 6 — Claude Code found 5 more). All were routes classified in approval_classes.py with no matching actual route in dream.py or costs.py. Includes: POST/DELETE /v1/dream, GET /v1/dream/pipeline, POST /v1/dream/pipeline/{pipeline_id}/confirm, and 7 cost-related routes that should be under /v1/costs/* (which were already properly classified there).

3. **PATCH /v1/dream/steps/{step_id} classification added** with `['write', 'cost_incurring']`. Previously fell back to generic PATCH prefix which lacked `cost_incurring`.

4. **orchestrator.py:323 `"result" in dir()` bug fixed** — `dir()` inside a function returns the symbol table; `"result" in dir()` always evaluates False. Replaced with `result = None` initialization + `if result is not None`. Affects retry-path cost reporting.

5. **PATCH /v1/dream generic fallback removed** — confirmed exact match (not prefix match) via `classify_route()` analysis. No actual PATCH /v1/dream route exists.

## Phase B1a — Audit Attribution Columns (Commit 6)

### Migration: `20260416_080000_audit_attribution_columns.sql`

Added 3 attribution columns + 1 schema evolution column to 4 audit tables:

| Column | Type | Purpose |
|---|---|---|
| `executor` | TEXT | Node/service that performed the action (ken, dream, gateway, buddy, system, forge, endpoint, sandbox, brain) |
| `on_behalf_of` | TEXT | Who authorized when a service acts for a user. NULL for direct user actions. |
| `source_request_id` | TEXT | W3C traceparent trace-id (32-hex) for end-to-end call chain forensics. |
| `schema_version` | SMALLINT DEFAULT 1 | Stripe Radar pattern — metadata field interpretation versioning. |

Tables modified:
- `alpha_approval_audit` — 4 columns
- `alpha_task_events` — 4 columns
- `alpha_watchdog_events` — **3 columns only** (already has `trace_id UUID` — view aliases it as `source_request_id`)
- `alpha_cloud_costs` — 4 columns + expanded `session_type` CHECK to include `'dream'`

Design decisions:
- All columns nullable, no default (except schema_version=1) — zero row rewrite on PG16
- CHECK constraint with `NOT VALID` on executor values — skips historical row scan
- `DROP CONSTRAINT IF EXISTS` before ADD — idempotent re-runs
- Rollback block included as SQL comments
- COMMENTs on every column (Google SRE pattern)

## Phase B1b — Audit Stream View (Commit 7)

### Migration: `20260416_080001_audit_stream_view.sql`

Created unified CloudTrail-style audit forensics infrastructure:

**4 intermediate per-table views** (Google Audit Logs pattern — each projects native schema to common shape):
- `v_audit_approval` — maps approval_audit to common (ts, executor, on_behalf_of, source_request_id, action, resource_type, resource_id, result, metadata, schema_version)
- `v_audit_tasks` — maps task_events
- `v_audit_watchdog` — maps watchdog_events, aliases `trace_id::text AS source_request_id`
- `v_audit_cloud_costs` — maps cloud_costs

**Top-level UNION view:**
- `alpha_audit_stream` — UNION ALL across 4 intermediate views
- **Admin-only** — explicit `WHERE current_setting('jarvis.role', true) = 'platform_admin'` in each UNION branch

**Critical security features:**
- `security_invoker = true` on ALL 5 views (Perplexity HIGH finding — without this, views bypass underlying table RLS)
- Verified on Brain: `SELECT reloptions FROM pg_class` shows `{security_invoker=true}` on all 5

**Partial indexes:**
- `idx_approval_audit_request_id` ON `alpha_approval_audit (source_request_id) WHERE source_request_id IS NOT NULL`
- `idx_task_events_request_id` ON `alpha_task_events (source_request_id) WHERE source_request_id IS NOT NULL`
- `idx_cloud_costs_request_id` ON `alpha_cloud_costs (source_request_id) WHERE source_request_id IS NOT NULL`
- `idx_watchdog_events_trace_id` ON `alpha_watchdog_events (trace_id) WHERE trace_id IS NOT NULL`

**Non-concurrent CREATE INDEX** used because `apply_migrations.sh` wraps files in single-tx (`-1` flag) which forbids `CONCURRENTLY`. Safe because all partial index columns are NULL for historical rows — build is sub-millisecond.

### Verification
- Admin query: `SET jarvis.role = 'platform_admin'; SELECT count(*) FROM alpha_audit_stream;` → **102 rows** ✅
- Non-admin query: `RESET jarvis.role; SELECT count(*) FROM alpha_audit_stream;` → **0 rows** ✅
