## §4 — Open architecture questions

### Q-A: dream.py fix shape

Two valid patterns surfaced earlier:
- (a) `rls_connection(request)` for routes — uses request-scoped JWT identity, RLS context flows from auth
- (b) Hardcoded `set_config('rls.role','platform_admin',true)` — service-level elevation, ignores JWT

Likely answer: (a) for normal user-driven writes, (b) for system writes (overnight dream loop). Needs you to confirm before writing the migration.

### Q-B: Watchdog route auth model

Same dilemma as dream. The watchdog routes are system-driven (Buddy agent loop), so probably want (b). But if a human ever triggers a watchdog endpoint manually, (a) makes more sense.

### Q-C: Phase 3 implementation scope per slab

70 callsites need RLSContext wiring. Options:
- 1 PR touching all 70 — fast but reviewer-hostile
- 1 PR per route group (~10 PRs) — slower but reviewable
- 1 PR per slab (~5 PRs) — middle ground

Worth deciding before opening the first Phase 3 implementation PR.
