## Scripts Standards — Porting from jarvis-core

This is a key carry-over decision. jarvis-core built up strong scripting standards
through trial and error. jarvis-alpha must inherit the patterns that worked and
discard the ones that caused pain.

### What Worked Well in jarvis-core — Bring These Over

**1. Commit scripts with built-in quality gates**
jarvis-core's `jarvis_commit.sh` runs ruff before every commit.
jarvis-alpha's `jarvisalpha_commit.sh` already does this + npm build + rsync.
Standard: every repo has one commit script. Never raw `git push`.

**2. `set -a && source ~/jarvis/.secrets` pattern**
Secrets exported before uvicorn starts so child processes inherit env.
This fixed the "uvicorn can't see secrets" bug in restart_forge.sh.
Standard: every start script uses this exact pattern. Never inline secrets.

**3. Pull-only script on Brain**
`jarvisalpha_pull.sh` — Brain never pushes, only pulls.
Air is the only machine that commits and pushes.
Standard: deploy direction is always Air → GitHub → Brain/Endpoint. Never reversed.

**4. `find ... -exec rm -rf {}` __pycache__ wipe before restart**
Stale bytecode caused silent import failures multiple times in jarvis-core.
Standard: always wipe `__pycache__` before `launchctl start`.

**5. LaunchAgent plist → wrapper script pattern**
Plist calls script. Script owns all env setup.
Plist never has env vars hardcoded.
Standard: plist = process supervisor only. Script = everything else.

**6. SHA256 hashing on all archived files**
`ship_publish.py` from jarvis-core introduced idempotent copy:
if dest exists and SHA matches → skip. This prevents duplicate writes on SMB.
Ported to `archive.py`. Standard: all file moves get hashed.

**7. Atomic file writes on SMB/NFS**
`copy2` to `.tmp` then `os.replace`. Never write directly to final destination.
Prevents partial files if SMB drops mid-write.
Standard: all Unraid writes are atomic.

**8. Structured error returns — never raise from services**
jarvis-core established: service functions return dicts with optional "error" key.
FastAPI routes catch and return 500 if error key present.
Standard: `brain/storage/`, `brain/ingest/`, `brain/memory/` all follow this.

### What Caused Pain in jarvis-core — Do Not Repeat

**1. Hardcoded IPs in source files (KI-8)**
7 files in jarvis-core have hardcoded `100.64.166.22` etc.
jarvis-alpha enforces: all IPs via `GATEWAY_URL` / `OLLAMA_URL` from config/env.
JARVIS invariant: never hardcode IPs, secrets, certs in any source file.

**2. `python3.12 -m ruff` instead of `ruff` binary**
Caused commit script failure today. ruff is installed as a binary, not a module.
Fix applied: `jarvisalpha_commit.sh` now calls `ruff format` directly.

**3. `pip3` (system) vs `.venv/bin/pip` confusion**
pdfplumber installed to system Python, not venv. Brain failed to start.
Standard: always install to `.venv/bin/pip install ... --quiet`.
Add to onboarding: run `which python` inside the service to confirm venv active.

**4. User path drift (swetagurnani vs jarvisbrain)**
Plist written on Air with `/Users/swetagurnani/` paths.
Fix required sed on Brain + re-commit from Air.
Standard: after every file-creation Cursor prompt, grep for `swetagurnani` to catch drift.

**5. nginx PID file corruption**
`nginx -s reload` fails with empty PID file when nginx was killed/restarted outside launchctl.
Fix: always stop/start via `launchctl unload` + `launchctl load`, never raw `nginx` binary.
