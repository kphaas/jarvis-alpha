### Critical Architecture Decisions Locked This Session

1. **Backend docs stay split by concern, not consolidated.** Big tech keeps `SERVICE_IDENTITY_MODEL.md`, `DB_CONTRACTS.md`, `PATTERNS.md`, `SERVICE_CONTRACTS.md`, etc. as separate files for different update cadences, audiences, and ownership. The `README.md` indexes them. NO `ALPHA_BACKEND_STANDARDS.md` consolidation needed beyond the index.

2. **Inline `check_scopes()` is the standard, not `@require_scopes` decorator.** Decorator was removed April 2026 for silently failing to enforce. Documented in `MIDDLEWARE_STACK.md` section 5.

3. **asyncpg JSONB pattern is `json.dumps(...)` on write AND `json.loads(...)` on read.** Pydantic silently coerces unparseable strings to empty defaults. Reference impl: `~/jarvis-alpha/brain/routes/briefings.py` `_parse_jsonb()` helper.

4. **Health endpoint two-endpoint standard (NEW this session).** Every JARVIS Alpha service exposes `/health` (liveness, zero deps) AND `/ready` (readiness, with deps). Added to `ALPHA_UI_STANDARDS.md` should also go into `PATTERNS.md` next session.

5. **Watchdog Pattern B (NEW this session).** Each node runs its own local watchdog. Brain centrally observes via `alpha_watchdog_events` table. Three layers: launchd KeepAlive (process death) → local watchdog (hung/zombie) → Brain observability (alerting). Each layer owns ONE failure mode.

## Architecture Notes for Next Session

### Watchdog Architecture — Pattern B (Verified Working)

```
   ┌────────────────────────────────────────────────────────┐
   │ launchd KeepAlive: true                                 │
   │   Restarts on PROCESS DEATH                              │
   │   (crash, OOM, kernel kill)                              │
   │   Owns: process lifecycle                                │
   └─────────────────────┬────────────────────────────────────┘
                         │
   ┌─────────────────────▼────────────────────────────────────┐
   │ Local Watchdog (forge_watchdog.py)                       │
   │   Polls /api/health every 60s                             │
   │   Restarts on APP HUNG (zombie/deadlock — KeepAlive can't │
   │     see this because process appears alive)               │
   │   Restarts via `launchctl kickstart -k`                  │
   │   Escalation: warn 1-2 → restart at 3 → circuit breaker  │
   │   Owns: application health                                │
   └─────────────────────┬────────────────────────────────────┘
                         │ POST /v1/watchdog/event
                         ▼
   ┌────────────────────────────────────────────────────────┐
   │ Brain alpha_watchdog_events table                        │
   │   Centralized observability                              │
   │   Pattern B = local watchdog + central aggregation       │
   │   Brain does NOT poll Sandbox directly                   │
   │   Owns: cross-node visibility                            │
   └────────────────────────────────────────────────────────┘
```

Each layer owns ONE failure mode. None can be removed without losing coverage. This is how big tech does it (Kubernetes liveness/readiness, Borg health checks, AWS ECS).

### Health Endpoint Two-Endpoint Standard

Every JARVIS Alpha service should expose:
- **`/health`** (liveness) — process alive? Zero dependencies. Instant return. Used by watchdog, launchd.
- **`/ready`** (readiness) — can serve traffic? Checks DB + critical deps. Returns 503 if degraded. Used by Brain mesh probe, ops dashboards.

**Anti-pattern:** Putting dependency checks in `/health`. A DB outage triggers cascading restart loops that prevent recovery. NEVER do this.

Today only Forge has both. Brain, Gateway, Endpoint should be retrofitted next session.
