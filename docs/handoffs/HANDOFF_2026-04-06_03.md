## Architectural Decisions Locked

### Self-healing pattern (big tech research)
- **Level 1**: launchd `KeepAlive` as dict with `Crashed: true` + `SuccessfulExit: false` + `ThrottleInterval: 30`
- **Level 2**: Python watchdog daemon, declarative config from `alpha_node_registry` (zero code changes to add a service)
- **Storage**: New `alpha_watchdog_events` table — state-change events only, NOT every check (Prometheus pattern)
- **Scope**: Hybrid — local watchdog watches local services; remote unhealthy services logged only
- **Defense in depth**: launchd is layer 1 (fast recovery), watchdog is layer 2 (catches launchd failures)

### Big tech reference
- Google Borgmon/Prometheus → Go binaries + declarative config + state-change events
- Python chosen here because: already used everywhere, asyncio handles 50+ services in <1s, can graduate to Go later if perf matters (it won't until 500+ services)

## Architectural Learnings

1. **asyncpg autocommit kills RLS** — Always wrap `set_config(..., true)` + queries in `conn.transaction()`. This was the chat-killer bug. Pattern: `try → async with conn.transaction(): → set_rls_user → queries → finally: reset_rls`
2. **jarvis_common is a real package** at `~/jarvis-alpha/common/jarvis_common/` — must be pip-installed editable. Don't create shim layers.
3. **LaunchAgent pattern**: Always use bash + start script + sourcing secrets + PYTHONPATH=common. Never run python directly. Brain, Buddy, Watchdog, Executor all follow this.
4. **Watchdog is for catching launchd failures**, not first-line defense. launchd KeepAlive typically restarts in <10 seconds — faster than the 60-second watchdog poll. The watchdog catches edge cases where launchd CAN'T fix it (port stuck, repeat-crash disable, etc.)
5. **Cursor uses Air username paths** — Always check for `/Users/swetagurnani` vs `/Users/jarvisbrain` in plists and `sed`-fix before deploy. Bit us twice this session.
6. **Component pattern is locked** — All new UI work follows: `types/X.ts` + `hooks/useX.ts` + `components/X/Component.tsx`. CostCenter (1901→59), Security (1875→292), Errors (983→268) all refactored. Mesh.tsx is next on the list.
7. **State-change-only events scale** — Empty events table = healthy system. Don't log every check.

## Known Issues / Open Questions

1. **launchd 5-second flapping pattern** — When Brain crashes within 5 seconds of restart 3+ times in a row, launchd may permanently disable the job until manual reload. Saw this in last night's logs (23:32:22 → 23:32:27 → 23:36:01 → 23:36:06 → 23:39:38 → 21-minute gap → 00:00:26). The 30s ThrottleInterval should help but needs validation.
2. **Watchdog only watches services with `node_type='service' AND is_active=true`** in registry. Adding a new service requires INSERT into the table, not code changes. This is correct, but undocumented for ops.
3. **Executor runs in single-process mode** — `MAX_CONCURRENT_GRAPHS = 3`. Should migrate to LaunchAgent worker pool at >5 concurrent. Backlog item.
