## Part 2 — Forge scripts rewrite

### Why this happened

Mid-session Ken tried to check the forge dashboard. Chain of issues surfaced:
1. `dist/` was missing on Sandbox (never built after Apr 21 rebuild)
2. After building, browser showed blank page — MIME type errors
3. `restart_forge.sh` kept failing with "address already in use" — race with LaunchAgent KeepAlive

### Root causes identified

| Issue | Root cause |
|---|---|
| UI not served | `ui/dist/index.html` missing — FastAPI returned JSON error |
| MIME errors after rebuild | Server running old code in memory (mount happened before dist existed) |
| Restart race | `restart_forge.sh` killed raw PID while LaunchAgent KeepAlive respawned within 10s |
| Ollama check in restart script | Wrong architecture — Ollama runs on Brain, not Sandbox |

### `forge_start.sh` (94 → 139 lines)

- `FORGE_CERT_DIR` env var (default `~/jarvis/certs`)
- `FORGE_PORT` env var (default 5001)
- Pre-flight checks fail LOUD: missing venv / dist / cert / key each exit 1 with specific reason
- Structured JSON startup events — `ts / level / service / node / event / status / reason`
- Test sidecar preserved with JSON event logging
- `exec uvicorn` pattern preserved (launchd manages PID directly)
- `--reload` still banned (documented with 2026-04-07 fix reference)

### `restart_forge.sh` (130 → 219 lines)

- **Core fix:** `launchctl bootout` + `launchctl bootstrap` instead of raw kill + nohup
- Verifies port is free after bootout; force-kill stragglers if any
- **Removed Ollama check** (wrong node — Ollama on Brain, not Sandbox)
- **Added Brain reachability check** (`curl ${JARVIS_ALPHA_BRAIN_URL}/health`) — graceful if env var missing
- Retry loop on health check (3 attempts, 2s between)
- Debug log tail (last 15 lines) on any failure
- Consistent `ok` / `warn` / `fail` / `info` helpers with color
- No spinners — each step prints once with clear result
- LaunchAgent PID verification after bootstrap

### Issue 1 — Sandbox cannot reach Brain

**Evidence:**
```
From Air:    curl -sk https://jarvis-brain.tail40ed36.ts.net:8186/health
             → {"status":"ok","node":"brain","service":"jarvis-alpha"} ✅

From Sandbox: curl -sk --max-time 5 ${JARVIS_ALPHA_BRAIN_URL}/health
             → (empty output, 5s timeout) ❌
```

**What we know:**
- `JARVIS_ALPHA_BRAIN_URL=https://jarvis-brain.tail40ed36.ts.net:8186` is correctly set in Sandbox `~/.secrets`

- Forge UI shows "Alpha Brain · offline" — forge correctly detecting the gap

1. Tailscale daemon on Sandbox not fully authenticated (post Apr 21 rebuild)

## Lessons from this session

1. **"What would big tech do?" is the right filter.** State/compute split, OrbStack, progressive secrets — all validated via Perplexity.

2. **Downloads don't auto-transfer from Claude artifacts.** Each artifact must be individually clicked. Tripped multiple times today.

3. **Git diff stale vs HEAD caused confusion.** Don't trust staged diffs during debugging — always check what's actually in the latest commit.

4. **Scope creep is real.** Started as Alpha-5 planning, extended into forge ops debugging. Flagging the pattern so next session stays scoped.

5. **LaunchAgent + manual restart = race condition.** `launchctl bootout` + `bootstrap` is the correct pattern, not raw kill + nohup. Codified in new `restart_forge.sh`.

6. **Pre-flight checks save hours.** New `forge_start.sh` exits loud with specific reason instead of silently starting a broken service. Today's MIME errors would have been a one-line error with the new script.

7. **Memory hit the 30-entry cap.** Removed #17 (now in V2) to add Alpha-5 entry #30. Worth periodic pruning — stable facts go in architecture docs, memory keeps active context.
