## Migration Pipeline (TD-22, TD-30)

### What was broken

1. `restart_alpha.sh` still called `alembic upgrade head` despite last session's Alembic deprecation. Every restart spewed a scary Python traceback (benign — continued past error — but dangerous if "fixed" naively).
2. `jarvisalpha_pull.sh` didn't run migrations at all. Committed migrations would never apply on Brain.
3. `apply_migrations.sh` was written Air-first — SSH'd to Brain via a key that doesn't exist on Brain itself. 3 password prompts + false "lock not acquired" error when run on Brain.
4. After fixing (3), pull script hard-failed on Gateway/Sandbox because `apply_migrations.sh` has a `jarvis-brain` hostname guard and those nodes aren't Brain.

### What we shipped

**`restart_alpha.sh`:** ripped Alembic block, added `apply_migrations.sh` call + hard-fail on migration error. Services will NOT start if migration fails.

**`jarvisalpha_pull.sh`:** added `apply_migrations.sh` call after git pull, before Brain restart block. Wrapped in hostname guard — only runs on `jarvis-brain`, skips cleanly with info log on Gateway/Sandbox/Endpoint.

**`apply_migrations.sh`:** stripped ALL SSH code. Added hostname guard at top. Runs local psql directly. Clean failure mode if run on wrong host.

### End-to-end proof

- **First real apply:** `004_taskgraph_columns.sql` was sitting unapplied in `brain/db/migrations/` — runner caught it, applied idempotently (all columns already existed, NOTICEs fired, no damage), recorded in `schema_migrations`. Pipeline proved on a live migration, not a synthetic test.

## Step 7 Discovery (via Claude Code on Air)

### Why we stopped Step 7 mid-design

After locking design decisions (7 SECURITY DEFINER functions, LOGIN writer role, Perplexity-validated hardening), schema discovery on actual tables surfaced:

1. `alpha_buddy_events` columns did NOT match handoff assumptions — no graph_id/step_id columns, payload goes in jsonb blob
2. `alpha_watchdog_events` already has an RLS policy checking `rls.user_id = 'system'` — a whole convention we didn't know existed
3. THREE GUC naming conventions in parallel use: `jarvis.*`, `app.*`, `rls.*`
4. `alpha_task_steps` + `alpha_task_graphs` have user-scoped RLS — not system tables, my School A assumption broke for those

Rather than continuing schema-dump-by-schema-dump, ran Claude Code on Air for full code discovery. One pass, 440-line report at `docs/STEP7_DISCOVERY.md`.

### What Claude Code found (10 open questions)

**Critical (blocks Step 7):**
- **OQ-8:** Two incompatible `alpha_buddy_events` schemas exist (migrations 005 + 008). Live schema depends on apply order. Time bomb.
- **OQ-4:** Buddy inserts to `alpha_buddy_events` are silently filtering out in production — RLS policy requires GUCs Buddy never sets. Buddy event feed partially broken for unknown duration.
- **OQ-1 + OQ-2:** `alpha_conversation_memory` has NO `ENABLE ROW LEVEL SECURITY` in any migration. All `jarvis.current_user` settings in memory.py protect nothing. Buddy bulk DELETEs run against an unprotected table. Core invariant we thought was enforced — isn't.

**Serious (pre-existing bugs):**
- **OQ-5 + OQ-6:** Route handlers set `jarvis.role = 'platform_admin'`; task graph policies check `= 'admin'`. Admin routes see zero task_events.
- **OQ-7:** `jarvis.is_admin` referenced in `semantic_isolation` policy but never set anywhere — unreachable escape hatch.

**Infrastructure:**
- 5 background writer pools (total max 23 concurrent connections): FastAPI app, executor, tasks/watchdog, buddy_agent, watchdog_agent
- 3 GUC conventions in active use: `jarvis.*`, `app.*`, `rls.*` — `rls_connection()` sets all 8 at once for request paths, each background writer uses ad-hoc subsets

## Lessons Locked Tonight

1. **Discovery before design — again.** Handoff #06 made this a rule. We almost violated it. Claude Code on Air caught 10 issues in one pass that schema-dump-by-schema-dump would have taken 2 more hours to surface.
2. **Handoff claims need verification, not trust.** Handoff #06 said tokens expire Apr 12. Reality: Apr 9. Off by 3 days, near-miss production incident.
3. **Perplexity validation caught real bugs.** EXCEPTION WHEN OTHERS RETURN FALSE was an anti-pattern I was about to ship. search_path hardening (`pg_catalog` first) is a real CVE class (CVE-2018-1058).
4. **"5 minute smoke test" was a 3 hour session.** Budget reality: if discovery reveals unknowns, a quick task becomes a full session. Don't force Step 7 on top of a tired foundation rebuild.
5. **`launchctl list` exit-code column lies.** Always verify with `ps aux` for ground truth.
6. **Scripts that modify themselves don't take effect until the next invocation.** Bash loads the whole script into memory first.
7. **Claude Code on Air is a force multiplier for read-only code discovery.** One pass, structured report, documented forever. Use it earlier next time.
8. **`set_config(..., true)` is transaction-scoped** — reinforced again. Known from Step 5.
9. **Big-tech migration pattern validated:** raw SQL + advisory lock + checksum + per-file transaction + runner invoked on deploy node (Brain) at deploy time. Alembic was correctly deprecated.
10. **GUC naming discipline matters.** Three parallel conventions (`jarvis.*`, `app.*`, `rls.*`) silently broke Buddy writes and admin task access. TD-37 is now P1.
