## Architecture Decisions Locked

### 1. LaunchAgent Flat-Directory Layout (TD-105/15)

All 16 plists consolidated into single flat `launchagents/` dir. Mirrors launchd runtime constraint (no subdirectories possible in `~/Library/LaunchAgents/`). Naming convention carries taxonomy via categorical prefix: `service.*`, `rotate.*`, `power.*`, `observability.*`. Matches systemd `/etc/systemd/system/` single-location pattern, Ansible roles-as-labels, k8s "organize by kind only when you have multiple kinds."

**Evidence base:** web-searched systemd/launchd/k8s conventions before locking. All flat. k8s "organize by kind" doesn't apply — we have one resource type (services), taxonomy is categorical, not structural.

### 2. Smart Worker / Dumb Orchestrator Deploy (TD-107)

Decoupled git pull from service restart classification. Before: `jarvisalpha_commit.sh` classified on Air what should restart, then gated pull on Brain/Gateway/Endpoint accordingly — but when plist files were deleted from repo, the `.sh$` regex didn't match and nodes silently drifted behind main.

After: commit script fans out git pull unconditionally to all runtime nodes. Pull script on each node self-classifies via `CHANGED_FILES` + `needs_restart_<node>()` functions. Conservative default: restart if uncertain. Matches k8s kubelet pulling pod manifests + CodeDeploy agent pulling deployment specs.

**Validated across 3 paths:** handoff-skip (3s), non-runtime (10s), full restart (29s for `.py` changes in `scripts/`). TD-113 logs a known false-positive (`.sh$` pattern matches install scripts). Acceptable — conservative default wins.

### 3. Session-Close Tooling Pattern

Reusable `scripts/session_close/` directory with two tools sharing one JSON manifest per session:

- `gh_sync.py` — GitHub Issues sync (labels, closes, create-and-close, opens)
- `handoff_scaffold.py` — auto-populated handoff template generator
- `manifests/YYYY-MM-DD.json` — session data, committed for audit trail

Matches Ansible playbook + inventory, k8s manifest + kubectl, Terraform plan + state. Dry-run default, `--execute` to fire, `--skip-existing` for idempotent resume. Per-run log to `/tmp/gh_sync_<date>.log`. Halt-on-error with resume instructions.

**Live-validated tonight against today's own session** — two bugs surfaced and fixed:
- Regex parser bug (stdout `split("/")[-1]` grabbed trailing garbage, closed-issue close failed)
- Skip-count semantics bug (skipped items didn't count toward success total, false halt)

Future sessions: ~45 min saved per session vs ad-hoc `/tmp/gh_sync_*.sh` scripts.

## Lessons Learned

- **Cursor multi-edit commit batching:** edits pile up in working tree until first commit sweeps them all together. Batching prompts without interim commits produces one mega-commit. Per-TD commit discipline requires commit-per-prompt, not commit-after-batch.
- **TD-107 conservative default prevented downtime.** `.sh$` pattern caught too much (TD-113) but the bias toward restart-when-uncertain kept cluster safe. Better false-positive than false-negative on deploy classification.
- **LaunchAgent drift detection discipline.** Handoff-01 claimed "executor was deleted in Alpha-2 rewrite" — wrong. Program-path-exists check before `launchctl bootout` prevented killing active TaskGraph executor. Always verify process identity before mutation.
- **Claude Code state-review pattern requires SCP.** Cursor is Air-only. Claude Code on Sandbox produces the output but file lives on Sandbox until manual SCP. Logged as TD-116 for codification.
- **Sandbox has two inconsistent git-auth paths** (TD-119). Commit script's SSH pull works; manual `jarvisalpha_pull.sh` fails on missing `GITHUB_TOKEN`. Two paths is a bug, not a feature.
- **Dry-run validates code paths, not data handling.** Both `gh_sync.py` bugs passed dry-run cleanly. First live run IS the integration test when no test repo exists. Accepted risk for iteration 1; future: log as TD for throwaway-repo test harness.
