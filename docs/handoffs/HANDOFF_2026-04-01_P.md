## Vision Locked This Session

### Human-Like Memory Architecture
Three tiers modeled on how human memory actually works:

| Tier | Table | Behaviour | Injected How |
|---|---|---|---|
| Working | alpha_conversation_memory (tier='working') | 24hr TTL, fades like short-term recall | Last N turns, always |
| Episodic | alpha_conversation_memory (tier='episodic') | Persistent, scored, vector search | HNSW search when semantically relevant |
| Semantic | alpha_semantic_memory | Permanent facts, never searched | Always injected, every request |

Buddy agent = hippocampus. Consolidates memory nightly exactly like human sleep.
Semantic tier is always-on — Jarvis never "searches" for Ken's name, it just knows it.

### Model Strategy — Central models.py
All model names in one file. Never hardcoded in routes or services.
Update brain/core/models.py only. Everything else imports from it.

### v2 Architecture Cross-Verify
Reviewed external "Jarvis v2" prompt against current alpha build:
- Already built: router, council, memory, ingest, storage, voice (core only), UI shell
- Net-new to build: TaskGraph engine, Planner agent, Executor agent, Buddy agent (started), tool permission layer
- Do NOT rebuild: memory (extend existing), overnight agent (port from jarvis-core, not dream_mode.py from scratch)
- Conflicts avoided: greenfield naming ignored, unified memory.py kept (not split into 5 files)

## Architecture Decisions Locked

| Decision | Choice | Rationale |
|---|---|---|
| JWT strategy | Shared RS256 issuer (jarvis-core), local validation in alpha | No runtime dependency, token survives core going away |
| Buddy process model | Separate LaunchAgent, own pool | Survives Brain crash, isolated logs, no memory leak cross-contamination |
| Buddy notifications | DB table + polling now, WebSocket next session | Ship today, transport swap is non-breaking |
| Memory scoring | Rule-based (access_count + recency + explicit save) | Fast, free, deterministic |
| Working memory eviction | 24hr TTL | Simple, no session tracking needed |
| Semantic tier storage | Separate table (alpha_semantic_memory) | Always injected full-read, no HNSW needed |
| Buddy loop interval | BUDDY_INTERVAL_SECONDS env var | Configurable per environment |
| Semantic cap | 50 facts per user | Prevents prompt bloat |
