## TD-197 — Watchdog SECDEF wrapper

**Title:** Watchdog read+write policies + over-broad grants
**Priority:** P1
**Owner:** Slab 4 (SECDEF + Shape B policies) + Slab 7c (REVOKE app/writer DML)
**Pre-flight (R5):** Watchdog process has zero `rls.role` set calls in code. SECDEF function with internal `set_config('rls.role','platform_admin', true)` is the only clean path.
**Risk today:** Defense-in-depth gap. No HTTP route reads alpha_watchdog_events. Active exploit needs future code that SELECTs the table under user RLS context.

### Big-tech alignment

Pattern matches AWS CloudTrail / GCP Audit Logs / Stripe internal events / Datadog audit log: never grant raw DML to app roles on telemetry tables; gate writes through a defined function with elevated privileges.

INTO` multi-row bug (P0003 fires every 60s when >1 pending row expires) + audit ALL SECDEF functions on FORCE-RLS tables for missing internal `set_config('rls.role','platform_admin', true)`. Canonical fix: rewrite `expire_pending_approvals` with CTE + array_agg pattern; add `set_config` escalation to all SECDEF on FORCE-RLS tables. Owner: Slab 4. Priority: P1.

**TD-202** — UI doesn't gracefully handle 403 `approval_required` response from DELETE /v1/threads (looks like generic error to user). Owner: UI work. Priority: P2.

**Pattern formally part of Slab 4 scope:** SECDEF functions writing to FORCE-RLS tables must internally `SET LOCAL rls.role = 'platform_admin'` (transaction-scoped) so the policy admin override path satisfies. Without this, every SECDEF write fails closed once the calling role loses BYPASSRLS. Big-tech precedent: AWS CloudTrail / GCP Audit Logs / Stripe internal events / Datadog audit logs — never grant raw DML to app roles on telemetry; gate writes through SECDEF with elevated privileges.
