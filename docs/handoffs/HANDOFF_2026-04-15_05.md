## What Was Done This Session

### 1. TaskGraphExecutor In-Process Class — DELETED (TD-53 CLOSED)

The in-process `TaskGraphExecutor` class in `executor.py` had 5 status values that violated Postgres CHECK constraints (`halted`, `retrying`, `complete`). It was dormant but a P0 time bomb. Decision: delete it entirely — LaunchAgent standalone executor is the only execution path.

- Removed entire class (268 lines deleted)
- Removed `_get_executor()` + `_executor` global from `tasks.py`
- Removed both `TaskGraphExecutor` imports from `tasks.py`
- `recover_stuck_graphs()` fixed to call module-level `_bind_executor_rls()` directly

### 2. tasks/watchdog.py — DELETED (TD-54 CLOSED)

Dead code. No LaunchAgent, no importers, never ran. Removed.

### 3. approve_graph Route — Pure Control Plane

`approve_graph` previously called `asyncio.create_task(_get_executor().run_graph(...))` — in-process execution that starved the uvicorn event loop.

Replaced with:
```python
async with rls_connection(request) as notify_conn:
    await notify_conn.execute(
        "SELECT pg_notify('graph_submitted', $1::text)", graph_id
    )
```

### 4. pg_notify LISTEN — Dedicated Persistent Connection

Previous implementation used `pool.execute("LISTEN graph_submitted")` — wrong pattern. Pool connections are borrowed and returned; listener died instantly.

Correct implementation:
- `notify_conn = await asyncpg.connect(dsn)` — dedicated connection outside pool
- `wake_event = asyncio.Event()` — bridges notification to main loop
- `_on_graph_submitted` callback sets `wake_event`
- `_wait_for_wake()` helper — returns on NOTIFY or poll timeout (whichever first)
- Graceful shutdown: `remove_listener` + `notify_conn.close()`

Result: graph submission → executor wakes in ~0ms. 10s poll as fallback.

### 5. Crash Loop Fixed

Executor was crashing every 30s due to `asyncpg.PostgresConnectionStatusError` — that attribute doesn't exist. Correct name is `asyncpg.PostgresConnectionError`. Fixed with `sed` one-liner. `__pycache__` purge required to clear stale `.pyc`.

### 6. Structured Exception Logging — All 3 LaunchAgents

Unhandled exceptions bypassed structured JSON logger and went raw to stderr (no timestamps). Fixed by wrapping `asyncio.run(main())` in try/except in all three agent entry points:

- `brain/tasks/executor.py` — `log.error("Executor crashed...")`
- `brain/agents/buddy_agent.py` — `logger.error("Buddy agent crashed...")`
- `brain/agents/watchdog_agent.py` — `logger.error("Watchdog agent crashed...")`

All crash tracebacks now appear in `.log` files with structured JSON timestamps. `_error.log` files will be empty going forward.

## Architecture State — Executor

```
FastAPI (Brain :8186)
  POST /v1/tasks/submit     → INSERT alpha_task_graphs + steps → pg_notify('graph_submitted')
  POST /v1/tasks/graphs/{id}/approve → UPDATE status='pending' → pg_notify('graph_submitted')

LaunchAgent (com.jarvis.alpha.executor)
  Dedicated notify_conn → LISTEN graph_submitted
  wake_event fires on NOTIFY (~0ms) OR poll timeout (10s fallback)
  Polls alpha_task_graphs WHERE status IN ('pending','running')
  Dispatches steps via dispatch.py (llm/code/tool/approval/condition/parallel_gate)
  Handles retries, approval gates, DAG dependency resolution
```

**Control plane and data plane are fully separated. No in-process execution anywhere.**
