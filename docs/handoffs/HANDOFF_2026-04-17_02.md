### Architecture

### Event Schema

Pull script emits events on stderr, one JSON object per line, sentinel-prefixed with `##EVT##`:

```json
##EVT##{"status":"ok","phase":"pull","node":"brain","from_hash":"eb3f3f5","to_hash":"7926c66","file_count":1,"dur_ms":460}
##EVT##{"status":"ok","phase":"migration","node":"brain","applied":0,"skipped":55,"failed":0,"dur_ms":1440}
##EVT##{"status":"ok","phase":"pycache","node":"brain","dur_ms":3150}
##EVT##{"status":"ok","phase":"restart","node":"brain","service":"alpha-brain","pid":6068,"dur_ms":4080}
##EVT##{"status":"ok","phase":"health","node":"brain","url":"https://jarvis-brain.tail40ed36.ts.net:8186/health","http_code":200,"dur_ms":40}
##EVT##{"status":"ok","phase":"restart","node":"brain","service":"alpha-buddy","pid":6117,"dur_ms":2120}
##EVT##{"status":"ok","phase":"tests","node":"brain","passed":133,"failed":0,"dur_ms":1400}
##EVT##{"status":"ok","phase":"complete","node":"brain","total_dur_ms":12967}
```

Phases: `pull · migration · pycache · restart · health · tests · dist_check · complete`
Statuses: `ok · fail · skip`

**Big-tech precedent:** k8s events, CloudWatch metric events, systemd journal events — structured-by-default.

### Renderer (`scripts/render_events.py`)

220-line Python stream filter. Stdin in, rendered output stdout:

- Reads stdin line-by-line
- `##EVT##` lines → parse JSON → render as `  ✅ step_name    detail    duration`
- Non-event lines → drop silently in NORMAL, passthrough dim-prefixed in VERBOSE
- Emits sentinels for bash consumption:
  - `##RENDER_FAIL##<json>` on any failed event
  - `##RENDER_DONE##<ms>` at terminal `complete` event
- Exit codes: 0 (all ok), 1 (any fail), 2 (parse error)

**Pattern:** single Python subprocess as stream filter. Matches CodeDeploy agent, not per-event subprocess spawn.

### Commit Script Rewrite (`jarvisalpha_commit.sh`, 419 lines)

Presenter + orchestrator. Bash handles SSH, renderer handles rendering. Clean separation of concerns.

**Helpers:**
- `phase_header` / `done_banner` — section delimiters
- `step_ok` / `step_fail` — aligned pre-deploy lines with timing
- `time_step` — wraps commands with duration capture
- `fmt_s` — seconds → "0.5s" / "5.0s" / "12s" / "60s"
- `lc` — portable lowercase (bash 3.2 compatible — macOS constraint)
- `remote_pull` — SSH + pipe through renderer + detect `##RENDER_FAIL##`
- `failure_box` — on failure, SSH back for logs + launchctl state, print debug box

**Verbosity levels (Ansible-style additive):**
- default: pretty NORMAL output
- `VERBOSE=1`: NORMAL + raw pull script output inline (dim-prefixed)
- `VERBOSE=2` (future): +raw `##EVT##` JSON

**Log file:** Every deploy tees to `/tmp/jarvisalpha_commit_YYYYMMDD_HHMMSS.log`. Grep-able post-hoc. Overridable via `LOG=/custom/path`.

**Halt-on-fail:** Any node's renderer exits non-zero → commit script halts, prints failure box, remaining nodes untouched.

## Architecture Decisions Locked This Session

1. **Event emission to stderr, not stdout** — keeps human output clean, events are metadata
2. **Sentinel prefix `##EVT##`** — unique pattern, won't collide with real log content
3. **Single Python subprocess as stream filter** — not per-event parse (matches CodeDeploy agent)
4. **Ansible-style additive verbosity** (`-v`, `-vv`, `-vvv`) — not a single boolean flag
5. **Halt-on-fail sequential fan-out** — never parallel without explicit safety (big-tech universal)
6. **Brain → Gateway → Endpoint order** — dependency chain (Brain = API contract source)
7. **Copy-validate-reload-verify** for nginx — atomic rename, not symlinks
8. **Capability-named scopes** — `cloud.call` not `gateway.cloud.call` — AWS IAM precedent
9. **Two-token pattern for services that both serve and call out** — documented in jarvis-standards
10. **Log file always written to `/tmp/jarvisalpha_commit_*.log`** — even on success, for audit
11. **Portable lowercase via `tr`** — bash 3.2 compatibility is non-negotiable (macOS constraint)
12. **"Do it right first time" as default** — session-level principle established

## Gotchas Caught & Fixed This Session

### 1. Bash 4+ `${VAR,,}` doesn't work on macOS

macOS ships bash 3.2 as `/bin/bash` for GPL v3 licensing reasons. `${VAR,,}` lowercase substitution is bash 4+. Caught on first real deploy of commit script v2 — 5 occurrences fixed with portable `lc()` helper using `tr '[:upper:]' '[:lower:]'`.

**Lesson:** Never use bash-4 features in JARVIS scripts. Always test with `/bin/bash -n` and prefer POSIX-ish constructs.

### 2. UTF-8 box-drawing chars cut by `head -c`

`phase_header` used `| head -c 60` to pad section dividers to fixed width. `─` is 3 bytes in UTF-8. Cutting at byte 60 often landed mid-character, producing `�` mojibake on terminal.

**Fix:** Remove `head -c` entirely. Let the format string set visual width directly.

**Lesson:** `head -c` operates on bytes, not characters. For UTF-8 content, use awk or printf with explicit char-counting.

### 3. `##RENDER_DONE##` sentinel leaking into displayed output

Renderer emits `##RENDER_DONE##12967` as last line for bash to extract duration. First version of commit script `cat "$tmp_out"` displayed everything including sentinels.

**Fix:** `grep -v '^##RENDER_DONE##\|^##RENDER_FAIL##' "$tmp_out"` before display. Sentinels still captured in full tee'd log for debugging.

**Lesson:** Design sentinels as explicit extract-then-strip patterns, not incidental noise.

### 4. SSH stderr handling across ssh layers

Events emit on stderr in pull script. When commit script runs `ssh host "bash pull.sh" 2>&1 | renderer`, stderr merges into stdout before piping. Worked correctly, but required verification — different SSH invocation patterns (with/without `-t`) behave subtly differently.

**Observed:** non-interactive SSH (no `-t`) correctly merges stderr→stdout with `2>&1`. Interactive `-t` mode sometimes buffers differently. For deploy automation, non-interactive is right.
