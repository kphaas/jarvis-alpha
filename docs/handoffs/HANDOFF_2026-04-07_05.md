## The Killer Bug (Never Forget)

`set_config(name, value, true)` is **transaction-scoped**. Calling it outside a transaction means the setting dies immediately. Old `rls_connection()` did:

```python
async with pool.acquire() as conn:
    await conn.execute("SET ROLE jarvis_alpha_app")
    await conn.execute("SELECT set_config(..., true)")  # dies instantly
    yield conn  # all queries see empty session vars
```

Fixed pattern:

```python
async with pool.acquire() as conn:
    await conn.execute("SET ROLE jarvis_alpha_app")
    try:
        async with conn.transaction():
            await conn.execute("SELECT set_config(..., true)")
            yield conn  # queries inside transaction see the values
    finally:
        await conn.execute("RESET ROLE")
```

**Symptom:** Direct psql with same SET statements returned 17 rows. Route returned `[]` for SELECT, 500 for INSERT (`new row violates row-level security policy`).

**Diagnosis path:** 6 messages of guessing until escalating to Perplexity. Perplexity nailed it on first response: "transaction scope mismatch."

**Lesson:** Escalate to Perplexity earlier when stuck on subtle Postgres/asyncpg behavior. Tooling beats intuition.

- Single household workspace = `personal` (Slack/Notion model)
- `alpha_profiles` = source of truth for humans
- `alpha_users` = projection populated via SECURITY DEFINER trigger
- workspace_id at PIN auth time, embedded in JWT
- Tenant isolation primitive: workspace_id (with profile_id today since claim was just added)

### JWT claims (after expansion)
- `user_id` (canonical) + `sub` (back-compat alias)
- `profile_id`, `display_name`, `role`, `actor_type`
- `workspace_id`, `max_rating`, `child_age`, `scopes`
- `iss`, standard JWT claims
- 30-day token, RS256, embedded at `/v1/auth/pin`

### RLS context (canonical pattern)
- Set per-connection in `rls_connection()`, NEVER via middleware
- Always wrapped in `conn.transaction()` for `set_config(..., true)` scoping
- Three naming conventions set on every connection (legacy reasons):
  - `app.*` — used by majority of policies
  - `jarvis.*` — used by `alpha_memory_isolation` (legacy, dead policy as of today)
  - `rls.*` — used by chat policies, watchdog ingest
- Fail-closed: missing user_id raises HTTPException 401

### Vault classification (6 tiers)
- `10_PUBLIC` — everyone + guests
- `15_KIDS` — admin + children only, NO guests (NEW)
- `20_PROJECTS` — admin + project members
- `30_FINANCE` — admin only
- `40_PRIVATE` — admin only
- `50_SECRETS` — denied via API for everyone, no exceptions

### Background agents (deferred to Step 7)
- Profile-bearing data → SECURITY DEFINER functions
- Infrastructure observability → dedicated writer role
- NEVER use `rls_connection()` (no request context)

### Middleware stack (after Step 5)
LIFO add order, FIFO request order:
1. `TraceIdMiddleware` — X-Trace-Id header
2. `CORSMiddleware` — Endpoint origin only
3. `JWTAuthMiddleware` — RS256 verification, populates `request.state`
4. `ApprovalMiddleware` — risk-tier classification
5. `RateLimitMiddleware` — per-user limits
6. `LogMiddleware` — structured access logs

**Deleted:** `AuthMiddleware` (duplicate stub that overwrote JWT with unverified base64), `RLSMiddleware` (no-op placeholder).
