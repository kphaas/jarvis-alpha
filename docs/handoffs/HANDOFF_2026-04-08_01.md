## Key learnings

### The scout-first pattern works
Manual curl testing today verified Fix #2 in ~5 minutes. Compare to: original bug diagnosis took 90+ minutes with 4 wrong leads because we skipped discovery. Lesson carried forward: always run Claude Code read-only scouts before writing Cursor prompts.

### TIER_RULES precedence is a security landmine
Prior session's Scout 4 caught a fatal flaw in the proposed `service_call` architecture: inserting `({service_call}, T2)` at the TOP of TIER_RULES would let any compromised service bypass destructive/admin checks. Correct placement is AFTER T5/T4 guards but BEFORE T3/T2/T1 cascade.

### Cursor prompt boilerplate (now standard)
Every Cursor prompt going forward includes environment rules: do not create venvs, do not install packages, only modify listed files, use existing venv, stop and report on missing imports. Combined with the pre-commit guard, this is defense-in-depth against the .cursor_tmp_venv incident recurring.

### Real ticket creation path is scripts/add_feature.py, not seed_backlog.py
Architecture doc was stale — claimed `memory/seed_backlog.py` was the path. That file is a 1-byte empty stub (created 2026-04-06 in commit `10ee885`). Real tool is `scripts/add_feature.py` on Sandbox, which does `INSERT OR IGNORE` to SQLite. Filed as F-157 (delete stub + update doc).
