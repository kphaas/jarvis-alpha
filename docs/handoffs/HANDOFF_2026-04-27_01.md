### Lock 3 — Failure mode

`RAISE EXCEPTION` with structured error (MESSAGE/DETAIL/HINT) on every violation. Standard SQLSTATE classes preferred (`28000` for auth, `42501` for privilege, `40001` for retry-safe collision); custom `J0xxx` codes only as secondary signal in DETAIL field. **Replaced** "INSERT-then-RAISE audit row" with pgAudit (Perplexity caught the rollback trap — pre-raise insert would roll back with the transaction).

### Lock 4 — Step 6 scope: 19 tables

`alpha_*` (17 tables) + `chat_*` (2 tables). NOT `vault_*` (Family Vault module owns those — separate migration when that module gets touched). Big-tech principle: module ownership is a hard migration boundary. Family Vault gets its own Step 6 equivalent later using the canonical template locked here.

### Lock 5 — alpha_cloud_costs FORCE flip

Currently the only RLS table without FORCE RLS. Will be flipped in Step 6, but with audit of every code path that writes as `jarvisbrain` first (FORCE flip means owner becomes subject to RLS too — silent breakage risk for migration scripts, ad-hoc psql, recovery tools). Big-tech: cost ledgers are the most-protected table in the stack.

### Lock 6 — GUC migration: Path B (atomic)

Code today uses `jarvis.role`, `jarvis.current_user`, `app.user_id`, `app.max_rating`, `app.workspace_id`. Step 7c migrates ALL to `rls.*` namespace in the same atomic migration:
- `jarvis.current_user` → `rls.user_id`
- `jarvis.role` → `rls.role`
- `app.user_id` → DROP (duplicate of `rls.user_id`)
- `app.max_rating` → `rls.max_rating`
- `app.workspace_id` → `rls.workspace_id`
- NEW: `rls.calling_agent` (tripwire from Perplexity defense-in-depth)

Final namespace: 5 GUCs, single `rls.*` prefix, clean.

### Lock 7 — alpha_dream_steps shape: admin-only

No user_id column. Big-tech YAGNI: don't pre-build per-user RLS for system-pipeline tables. EXISTS-to-parent JOIN is overhead for telemetry nobody asked for. If/when needed, easy future migration.

### Lock 8 — Bug fixes folded into Step 6

- `alpha_task_events` — policy compares GUC against literal string `'admin'` (latent vuln if any user has `user_id='admin'`). Replace with canonical Shape B (`rls.role = 'platform_admin'`).
- `alpha_watchdog_events` — `watchdog_events_system_write` references retired `rls.user_id` GUC, WITH CHECK silently always-false. Drop dead policies, replace with canonical.
- `record_watchdog_event` — registered twice with different return types (void → uuid). Keep latest, drop original.

### Lock 9 — app.* migration (Q4)

`app.max_rating` and `app.workspace_id` migrate to `rls.*` in Step 7c too. Big-tech: single namespace per concern. Half-migrated state is corrosive forever.

### Lock 10 — Slab 1 (pgAudit source build)

**Reversed twice during session — final lock = source build.** Reasoning:
- Big tech (Stripe, GitHub, Heroku, AWS RDS, GCP) all use pgAudit
- Industry-standard audit format, monitoring tools recognize it natively

### SQLSTATE convention (locked Slab 1)

| Failure type | SQLSTATE | When |
|---|---|---|
| Wrong agent (GUC tripwire mismatch) | `28000` | Function reads `rls.calling_agent`, doesn't match |
| Wrong role for action | `42501` | Function checks `rls.role`, caller can't act |
| Scope violation | `28000` | Caller not platform_admin and not row owner |
| GUC missing entirely | `28000` | `rls.calling_agent IS NULL` — agent misconfigured |
| Idempotent retry collision | `40001` | Postgres retry signaling (matches existing pattern) |
| Internal invariant violation | `XX000` | Should never fire; page on it |

Custom J-codes (in DETAIL only, never ERRCODE): `J0001` cross-agent call, `J0002` pool contamination, `J0003` forced role downgrade.
